================================================================
A. PoC PRD: Ownlyfans
================================================================

Tech Stack: TypeScript + SUI + Walrus + Seal

================================================================
1. 概念驗證目標 (PoC Goal)
================================================================

核心驗證假設：
「將內容購買者轉變為銷售合夥人，能有效提高內容外流的機會成本，並激發粉絲推廣的正面動機。」

驗證指標 (KPI)：
- 粉絲產生推廣行為的比例 ≥ 30%
- 透過推廣連結購買的轉換率 ≥ 10%

================================================================
2. 核心功能範圍 (Scope of Work)
================================================================

2.1 創作者 / 內容發布 (Creator Side)
-----------------------------------
C-1: 內容上傳與定價  
- 創作者可上傳一條測試內容 (圖片或影片)。  
- 系統透過 Walrus SDK 上傳內容，返回 blob_id。  
- 上傳後設定內容價格與分成比例。  
- 不需鑄造 NFT，內容即儲存在 Walrus。  

C-2: 推廣分成設定  
- 創作者可設定推廣分成比例（例如 15%）。  
- 該比例寫入智能合約，供後續自動拆分收益使用。

2.2 粉絲 / 推廣者互動 (Fan / Promoter Side)
-----------------------------------
F-1: 內容購買與存取  
- 粉絲連接錢包購買內容存取權。  
- 智能合約驗證付款成功後，使用 Seal 授權該粉絲的錢包地址。  
- 粉絲通過 Seal SDK 解鎖並觀看內容。  

F-2: 專屬推廣連結生成  
- 購買完成後，系統生成綁定粉絲錢包地址的推廣連結：  
  例如 `...?ref=0xFanWalletAddress`。  

F-3: 收益追蹤儀表板  
- 粉絲可查看推廣連結點擊與轉換次數。  
- 僅簡易版統計，不含進階分析。

2.3 鏈上核心機制 (Smart Contract Logic - PoC Core)
-----------------------------------
S-1: 交易歸因與拆分  
- 新用戶透過推廣連結購買內容時，合約自動識別 `ref` 地址。  
- 依照預設比例 (例如 15%) 拆分收益：  
  - 15% → 推廣者  
  - 85% → 創作者  

S-2: 防自推廣機制  
- 若購買者地址與 `ref` 地址相同，交易自動拒絕。

S-3: 防重複分潤機制  
- 相同交易哈希不可重複觸發分潤事件。

================================================================
3. 排除範圍 (Out of Scope for PoC)
================================================================
- NFT 發行與交易（本階段僅上傳內容至 Walrus）  
- 多層級推廣 (僅單層 referral)  
- 變動比例或複雜分潤邏輯  
- 多媒體格式支援（僅圖片 / mp4）  
- 完整前端 UI 設計與優化  
- 代幣經濟與治理模型  
- 訂閱制功能  
- DAO / 社群共創功能  

================================================================
4. 系統架構 (Tech Architecture)
================================================================

Frontend:
- React + TypeScript + Vite
- React Query for data fetch
- Wallet connection via SUI SDK
- Basic dashboard (creator / fan)

Backend (Smart Contracts):
- SUI Move modules
  - Content registry (記錄 blob_id, price, ref_split_ratio)
  - Referral split & validation
  - Transaction logging

Storage:
- Walrus SDK → 上傳內容文件，返回 blob_id
- Seal SDK → 加密存取控制（限付費錢包地址解鎖）

Payment:
- SUI Coin or USDC on SUI network
- 智能合約即時分潤轉帳 (split_transfer)

Analytics (Minimal):
- 鏈上事件 (Event logs) 紀錄點擊與購買轉換
- 前端簡單展示（無需後端資料庫）

================================================================
5. 驗證方法 (Evaluation Plan)
================================================================
1. 實際邀請 3 位創作者與測試粉絲進行購買/推廣。  
2. 觀察推廣轉換率與內容外流情況。  
3. 驗證假設是否成立：粉絲的「合夥人動機」是否明顯提升。  

================================================================
6. 理論背景 (Contextual Analysis)
================================================================

6.1 經濟學角度：從負面到正面外部性
- Patreon 模式：用戶外流為負面外部性。  
- Web3 模式：粉絲推廣成為正面外部性，守護內容即守護自身收益。  

6.2 博弈論角度：從囚徒困境到協同博弈
- 傳統：背叛成本低，容易外流。  
- Ownlyfans：理性選擇為合作推廣，共同最大化分潤。  

6.3 心理學角度：從消費者到合夥人
- 用戶從「購買者」升級為「貢獻者」，形成互惠心理與內容保護意識。  

================================================================
7. 未來擴充功能 (Future Extensions)
================================================================
E-1: 粉絲代幣 (Fan Token)  
- 粉絲可持有創作者發行的代幣，用於內容解鎖或直接套現交易。  

E-2: 創作者 NFT 發行  
- 創作者可將內容鑄造成限量 NFT，粉絲可收藏或轉售。  

E-3: 訂閱制功能  
- 支援粉絲訂閱創作者，定期自動授權 Seal 存取權。  

================================================================
8. 結論 (Summary)
================================================================

Ownlyfans PoC 透過 Walrus (去中心化儲存) 與 Seal (加密存取)，
結合 SUI 智能合約的透明分潤機制，
將粉絲從被動消費者轉化為主動推廣合夥人。

最終目標：
以最小實作驗證「正向激勵能否減少內容外流」，
並為後續代幣化、NFT、訂閱制等功能鋪路。
